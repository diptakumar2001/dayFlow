# DayFlow — notes for Claude

Daily planner for students. Plain HTML/CSS/JS: no framework, no bundler, no backend. `README.md` lists the
features; don't re-read it to learn the structure, this file covers that.

## Run
- Browser: open `index.html`, or serve with `python -m http.server 5173` (`.claude/launch.json` has it as "dayflow").
- Build: `python build_artifact.py` → `dist/dayflow-single.html` (one file), `dist/artifact.html`, and `www/`.
- Phone app (Capacitor 8): `npm run android` / `npm run ios` (build + `cap sync` + open the IDE). iOS needs a Mac.
  `android/` is generated by Capacitor; only edit it for native settings. Never edit `www/` (it's rebuilt).

## Files (scripts load in this order)
- `js/vendor/supabase.js` (supabase-js UMD, don't edit) and `js/config.js` (`CONFIG`: Supabase URL, anon key, siteUrl).
- `js/platform.js` — `Platform`: storage, reminders, files, back button. Web APIs in a browser, Capacitor plugins in the app.
- `js/store.js` — `DateUtil` (dates are `"YYYY-MM-DD"` keys, times are minutes after midnight) and `Store`
  (the task array, `normalize()`, undo, repeats, overlaps, leftovers, to-dos, search, backup).
- `js/sync.js` — `Sync`: sign up/in/out, password reset, delete account, `push()`/`pull()` of task rows,
  settings. Disabled (device-only mode) when `CONFIG` is empty.
- `js/timeline.js` — `Timeline`: day/week grid rendering, drag/resize (touch = hold first), keyboard moves.
- `js/app.js` — everything else: header, sidebar lists, task form, quick add parser (`parseQuick`), settings,
  backup UI, reminders, shortcuts. `init()` runs after `Platform.ready()`.
- `css/styles.css` — theme tokens at the top (light + dark), grid areas for desktop vs phone at the bottom.

## Rules
- One `tasks` array is the source of truth. Change it only through `Store` mutations (they snapshot for undo),
  then call `render()`. Toast every change with the `undoAction`.
- New task fields: add a default in `normalize()` so old saved data still loads.
- `start: null` means a to-do (no time); `tasksOn()` skips those. Repeats never get per-day edits: changing one
  day adds it to `skipDates` and makes a one-off copy (`Store.detach`).
- Accounts: each account has its own store key (`dayflow.u.<userId>`, guest = `dayflow.v1`). Sync compares
  tasks with `Store` baseline (`changes()` / `markSynced()` / `applyRemote()`), so mutations never call Sync.
- Supabase only inside `sync.js`. Data safety comes from row-level security in `supabase/schema.sql`; the anon
  key is public, the service_role key must never be in the client. Schema changes go in `schema.sql`.
- Device features only through `Platform` — never call `localStorage`, `Notification` or downloads directly.
- Tasks can't cross midnight. Overlap confirmation follows `settings.warnOverlaps`.
- Style: IIFE modules, short "why" comments, escape user text with `esc()` before putting it in HTML.

## Check your work
Accounts without a real project: load the page with a stand-in `window.supabase` (in-memory tables filtered by
user) in place of `js/vendor/supabase.js` + `js/config.js`.

No test suite. Start the server, open the page in the browser pane, check the console for errors, and test the
flow you changed (the quick add preview in `#quickPreview` is the fastest way to test the parser). Check phone
width with the mobile viewport. Run `python build_artifact.py` after changes and `npx cap sync` for the app.

## Saving tokens
Read only the file you're changing. `app.js` is the largest: Grep for the function name instead of reading it all.
